# Занятие 7. Спелчекеры, нормализация и лингвистические инструменты

## Роль занятия в курсе
Занятие добавляет компонент, который часто нужен сообществам напрямую: проверка орфографии, нормализация, словари и простые инструменты письма. Итог - прототип спелчекера или нормализатора.

## Лекция, 90 минут

### Слайд 1. Почему спелчекер важен
Текст на слайде:
- Поддержка письма и образования
- Улучшение OCR и ASR-постобработки
- Нормализация корпуса
- Обнаружение ошибок в данных

Комментарии докладчика:
Спелчекер - не второстепенный инструмент. Для языкового сообщества он может быть понятнее и полезнее, чем абстрактная ML-модель.

### Слайд 2. Типы орфографической вариативности
Текст на слайде:
- Ошибки набора
- Варианты орфографии
- Диалектные различия
- Заимствования
- Нестабильная письменная норма
- Ошибки OCR и ASR

Комментарии докладчика:
Нельзя автоматически считать все варианты ошибками. Для некоторых языков “норма” обсуждается или меняется. Инструмент должен быть настраиваемым и документированным.

### Слайд 3. Подходы к спелчекеру
Текст на слайде:
- Словарный: Hunspell-стиль
- Правила и морфология
- Edit distance и кандидаты исправлений
- Нейросетевой seq2seq
- LLM как ассистент проверки, не как источник нормы

Комментарии докладчика:
Для курса реалистичен словарный или гибридный baseline: словарь + edit distance + правила. Нейросетевой подход требует больше данных и аккуратной оценки.

### Слайд 4. Что нужно для словарного baseline
Текст на слайде:
- Список словоформ
- Частотность
- Разметка допустимых вариантов
- Правила аффиксов, если есть
- Набор тестовых предложений

Комментарии докладчика:
Даже частотный список из очищенного корпуса уже помогает. Но его нужно вручную проверить: веб-корпус может содержать ошибки, имена, русские или английские вставки.

### Слайд 5. Нормализация vs исправление
Текст на слайде:
- Исправление: ошибка -> правильная форма
- Нормализация: вариант -> выбранный стандарт
- Транслитерация: письменность A -> письменность B
- Все преобразования должны быть явно размечены

Комментарии докладчика:
Это важное различие. Нормализация может быть политически и культурно чувствительной. В курсе лучше говорить о вариантах и выбранной рабочей норме, а не о “правильном” языке без контекста.

### Слайд 6. Оценка спелчекера
Текст на слайде:
- Precision: сколько предложенных исправлений верны
- Recall: сколько ошибок найдено
- False positives особенно опасны
- Отдельно оценивать редкие и диалектные формы

Комментарии докладчика:
Плохой спелчекер может навредить, если помечает правильные формы как ошибки. Для малоресурсных языков лучше осторожный инструмент с высоким precision.

### Слайд 7. Интеграция с другими треками
Текст на слайде:
- OCR: исправление частых распознавательных ошибок
- ASR: нормализация транскриптов
- MT: терминология и словари
- Корпус: контроль качества

Комментарии докладчика:
Спелчекер должен использовать результаты всех предыдущих занятий: очищенный корпус, OCR-ошибки, ASR-ошибки, параллельные тексты и словари.

### Слайд 8. Артефакт занятия
Текст на слайде:
- `wordlist.tsv`
- `accepted_variants.tsv`
- `spellchecker_rules.md`
- `spellchecker_demo.py` или notebook
- `spellchecker_eval.md`

Комментарии докладчика:
Даже простой прототип, который показывает неизвестные слова и предлагает кандидатов, уже полезен. Главное - не скрывать ограничения.

## Семинар, 90 минут

### Практика 1. Частотный словарь, 20 минут
Команды строят `wordlist.tsv`:
- word
- count
- source_count
- status: accepted / unsure / reject
- notes

### Практика 2. Ошибки и варианты, 20 минут
Команды собирают 30 примеров:
- OCR-ошибка
- ASR-ошибка
- опечатка
- орфографический вариант
- заимствование

### Практика 3. Baseline-спелчекер, 30 минут
Минимальная логика:
- если слова нет в словаре, отметить
- предложить кандидатов по edit distance
- не исправлять автоматически без подтверждения
- сохранять лог решений

### Практика 4. Оценка, 20 минут
Команды проверяют 20 предложений:
- сколько ошибок найдено
- сколько правильных слов ошибочно помечено
- какие правила опасны
- что нужно спросить у носителей

Промпт для агента:
```
На основе списка слов, частот и примеров ошибок предложи осторожную схему спелчекера.
Отдельно выпиши правила, которые нельзя применять автоматически.
Сформируй план ручной проверки с носителем языка.
```

## Домашнее задание
1. Подготовить словарь минимум на 300 словоформ или объяснить ограничение.
2. Создать 50 тестовых примеров для проверки.
3. Описать false positives и риски нормализации.
4. Подготовить демо или псевдодемо для финальной презентации.

## Выход занятия
- `wordlist.tsv`
- `spellchecker_rules.md`
- Прототип спелчекера или нормализатора
- `spellchecker_eval.md`

## Связь с летней школой
Для летней школы нужно подготовить сессию проверки словаря с носителями: спорные формы, варианты, диалектные слова, правила исправления и приоритеты образовательного применения.
