# Занятие 6. Параллельные тексты, LBCM-alignment и машинный перевод

## Роль занятия в курсе
Занятие связывает сбор текстов с машинным переводом. Главный результат - небольшой параллельный датасет, выровненный с помощью LBCM-подхода, и baseline для перевода.

## Терминологическое уточнение
В рамках курса LBCM используется как практический блок LaBSE-based Cross-lingual Bitext Mining/Matching: поиск и выравнивание параллельных или сопоставимых фрагментов через многоязычные эмбеддинги, similarity scoring и ручную валидацию.

## Лекция, 90 минут

### Слайд 1. Зачем нужны параллельные тексты
Текст на слайде:
- Перевод
- Словари и терминология
- Оценка качества моделей
- Обучающие материалы
- Связь с доминирующим языком региона

Комментарии докладчика:
Параллельные данные часто являются самым узким местом для машинного перевода. Для малоресурсных языков даже несколько сотен проверенных пар предложений могут быть значимым ресурсом.

### Слайд 2. Источники параллельных данных
Текст на слайде:
- Учебники и двуязычные материалы
- Религиозные тексты
- Сайты администраций и СМИ
- Словари и фразовые списки
- Полевой перевод коротких текстов

Комментарии докладчика:
Нужно обсуждать доменную ограниченность. Религиозные тексты могут быть большими, но не отражают современную повседневную речь. Учебные материалы полезны, но часто содержат искусственные фразы.

### Слайд 3. Типы выравнивания
Текст на слайде:
- Document alignment
- Paragraph alignment
- Sentence alignment
- Phrase and word alignment
- Comparable corpora mining

Комментарии докладчика:
Не всегда есть идеально параллельные тексты. Иногда есть две версии новости, пересказ, учебный перевод или тексты на похожую тему. Тогда задача становится mining, а не простым выравниванием.

### Слайд 4. LBCM-пайплайн
Текст на слайде:
1. Разбить документы на сегменты
2. Получить multilingual embeddings
3. Посчитать similarity
4. Найти кандидатов
5. Отфильтровать по длине, языку, score
6. Проверить вручную

Комментарии докладчика:
Главная идея: предложения с похожим смыслом должны быть близки в многоязычном embedding-пространстве. Но score не заменяет экспертизу, особенно для родственных языков, диалектов и коротких фраз.

### Слайд 5. Риски alignment
Текст на слайде:
- Ложные пары
- Слишком свободный перевод
- Пропуски и перестановки
- Смешение языков
- Утечка тестовых данных
- Неподходящий домен

Комментарии докладчика:
Alignment может выглядеть убедительно, но быть неверным. Для финального датасета нужно хранить score, источник и статус ручной проверки.

### Слайд 6. Baseline машинного перевода
Текст на слайде:
- Готовая multilingual MT-модель
- Few-shot prompting как baseline
- Fine-tuning при достаточном объеме
- Оценка: chrF, BLEU, COMET, ручная проверка

Комментарии докладчика:
Для малоресурсных языков BLEU часто нестабилен. chrF может быть полезнее на малых данных. Ручная оценка обязательна, особенно если орфография вариативна.

### Слайд 7. LLM и перевод
Текст на слайде:
- LLM может помогать с черновым переводом
- Нужна маркировка synthetic data
- Нельзя смешивать человеческий и синтетический перевод без метаданных
- Для обучения модели synthetic data может быть полезен, но рискован

Комментарии докладчика:
LLM может создавать fluent hallucinations. В малоресурсном языке она может подменять язык похожим или доминирующим. Все синтетические данные должны быть явно помечены.

### Слайд 8. Артефакт занятия
Текст на слайде:
- `parallel_candidates.tsv`
- `parallel_verified.tsv`
- `alignment_report.md`
- `mt_baseline_report.md`

Комментарии докладчика:
Цель занятия - не обязательно обучить сильный переводчик. Более надежный результат - качественный маленький параллельный набор и понимание, сколько данных нужно для следующего шага.

## Семинар, 90 минут

### Практика 1. Подготовка сегментов, 20 минут
Команды берут два документа или две коллекции текстов и создают:
- `source_segments.tsv`
- `target_segments.tsv`

Поля:
- `segment_id`
- `doc_id`
- `text`
- `language`
- `source`

### Практика 2. LBCM-кандидаты, 30 минут
Команды используют готовые многоязычные эмбеддинги или агентно подготовленный скрипт:
- кодируют сегменты
- считают cosine similarity
- выбирают top-k кандидатов
- сохраняют `parallel_candidates.tsv`

### Практика 3. Ручная валидация, 20 минут
Команды размечают 30 кандидатов:
- good translation
- partial translation
- same topic only
- wrong
- unsure

### Практика 4. MT baseline, 20 минут
Команды запускают перевод одним доступным способом:
- готовая MT-модель
- LLM-prompt baseline
- словарный baseline для отдельных терминов

Промпт для агента:
```
Проанализируй таблицу кандидатов параллельных предложений.
Предложи правила фильтрации по similarity, длине, языку и ручному статусу.
Составь отчет о том, какие пары можно использовать для обучения,
какие только для анализа, а какие нужно исключить.
```

## Домашнее задание
1. Подготовить минимум 100 кандидатов параллельных сегментов.
2. Вручную проверить минимум 50.
3. Сделать baseline-перевод на 20 примерах.
4. Описать, какой объем параллельных данных нужен для летней школы.

## Выход занятия
- `parallel_candidates.tsv`
- `parallel_verified.tsv`
- `alignment_report.md`
- `mt_baseline_report.md`

## Связь с летней школой
Занятие показывает, какие тексты стоит переводить на месте: списки фраз, короткие рассказы, учебные тексты, доменная терминология. Для летней школы можно заранее подготовить translation elicitation kit.
