# Занятие 8. Финальная интеграция, артефакты и план летней школы

## Роль занятия в курсе
Последнее занятие собирает результаты в понятные артефакты: датасеты, модели, пайплайны, отчеты и план летней школы. Главный результат - не презентация ради презентации, а проверяемый пакет работы.

## Лекция, 90 минут

### Слайд 1. Что считается результатом курса
Текст на слайде:
- Датасет с data card
- Модель с model card
- Пайплайн с инструкцией запуска
- Демо для сообщества или преподавателей
- План полевого сбора для летней школы

Комментарии докладчика:
Результаты могут быть разными по технической сложности. Важнее, чтобы они были честно описаны, воспроизводимы и пригодны для следующего этапа.

### Слайд 2. Минимальный финальный пакет
Текст на слайде:
- `README.md`
- `DATA_CARD.md`
- `MODEL_CARD.md`, если есть модель
- `pipeline.md` или notebook
- `eval_report.md`
- `summer_school_plan.md`

Комментарии докладчика:
Если команда не успела обучить модель, это не провал. Качественный датасет и сильный план сбора могут быть ценнее слабой модели без документации.

### Слайд 3. Model card
Текст на слайде:
- Назначение модели
- Данные обучения
- Метрики
- Ограничения
- Известные ошибки
- Нерекомендованное использование
- Контакт и версия

Комментарии докладчика:
Для ASR, OCR, перевода и спелчекера model card должен прямо указывать, на каких данных модель проверялась и где она не должна применяться.

### Слайд 4. Evaluation report
Текст на слайде:
- Что измеряли
- На каком тесте
- Какие метрики
- Примеры ошибок
- Что нужно улучшить
- Что нельзя утверждать по этим данным

Комментарии докладчика:
Сильный отчет не скрывает слабости. Для малоресурсных языков честный анализ ошибок часто важнее красивой общей метрики.

### Слайд 5. Интеграция пайплайнов
Текст на слайде:
- Web corpus -> cleaning -> spellchecker
- OCR -> correction -> text corpus
- ASR -> transcript -> text corpus
- Parallel alignment -> MT baseline
- Все артефакты связаны метаданными

Комментарии докладчика:
Курс должен показать, что отдельные компоненты не изолированы. OCR и ASR дают тексты, тексты помогают спелчекеру, параллельные данные помогают переводу, все вместе готовит летнюю школу.

### Слайд 6. Агентная проверка финального пакета
Текст на слайде:
- Проверить структуру файлов
- Найти недостающие метаданные
- Сравнить README с реальным содержимым
- Сформировать список рисков
- Подготовить чек-лист публикации

Комментарии докладчика:
Агент хорошо работает как reviewer. Он может найти несоответствия: README обещает модель, но файла нет; data card не содержит лицензии; evaluation report не указывает test set.

### Слайд 7. План летней школы
Текст на слайде:
- Регион и языки
- Партнеры и контакты
- Какие данные собираем
- Оборудование и роли
- Этический протокол
- Расписание полевой лаборатории
- Ожидаемые артефакты

Комментарии докладчика:
Летняя школа должна строиться на выводах курса. Нужно понять, какие гипотезы подтвердились, где данных не хватает, какие команды готовы вести станции: ASR, OCR, перевод, спелчекер, корпус.

### Слайд 8. Финальная защита
Текст на слайде:
- Проблема
- Данные
- Метод
- Результат
- Ошибки и ограничения
- Что дальше
- Что нужно от летней школы

Комментарии докладчика:
Финальная защита должна быть короткой и предметной. Не надо продавать результат как завершенное решение, если это прототип. Важно показать, что команда понимает качество и следующий шаг.

## Семинар, 90 минут

### Практика 1. Финальная сборка, 25 минут
Команды приводят проект к структуре:
```
project/
  README.md
  data/
  reports/
  notebooks/
  models/
  DATA_CARD.md
  MODEL_CARD.md
  summer_school_plan.md
```

### Практика 2. Агентный review, 20 минут
Промпт:
```
Проверь финальный пакет проекта по малоресурсному языку.
Найди несоответствия между README, данными, отчетами и заявленными результатами.
Составь список блокеров перед публикацией, список желательных улучшений
и список задач для летней школы.
```

### Практика 3. Финальные презентации, 30 минут
Каждая команда показывает:
- что было целью
- какие данные собраны
- какие модели или пайплайны сделаны
- какие метрики получены
- какие ошибки обнаружены
- что нужно делать дальше

### Практика 4. Общий план летней школы, 15 минут
Группа собирает общий документ:
- приоритетный регион
- список языков
- станции работы
- минимальное оборудование
- партнеры
- риски
- план доработки до следующего года

## Домашнее задание после курса
1. Довести финальный пакет до состояния публикации или внутреннего архива.
2. Подготовить письмо потенциальным партнерам летней школы.
3. Составить список оборудования и бюджета.
4. Подготовить три сценария летней школы: минимальный, реалистичный, расширенный.

## Выход занятия
- Финальный проектный пакет
- Датасет, модель, пайплайн или демо
- `eval_report.md`
- `summer_school_plan.md`
- Список задач на следующий этап

## Критерии оценки курса
- Данные описаны и легально понятны
- Пайплайн воспроизводим
- Метрики честно посчитаны
- Ошибки проанализированы
- Риски для сообщества указаны
- Есть практический следующий шаг

## Связь с летней школой
Финальный документ должен ответить на три вопроса:
1. Какие данные мы можем собрать до школы?
2. Какие данные нужно собирать только на месте?
3. Какие артефакты реально получить за 1-2 недели интенсивной работы?
