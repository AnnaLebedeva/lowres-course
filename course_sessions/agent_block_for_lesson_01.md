# Блок для занятия 1. AI-агенты в языковой лаборатории

## Слайд. Что такое агент
Текст на слайде:
- Агент: система, способная совершать автономные действия во внешней среде для достижения поставленных целей
- Интеллектуальный агент: планирует действия, реагирует на изменения, взаимодействует с человеком и другими агентами
- AI-агент: агент на базе генеративного ИИ, который планирует, действует, реагирует и взаимодействует

Комментарии докладчика:
Здесь важно дать не маркетинговое, а рабочее определение. Обычный чат отвечает текстом. Агент получает цель и может действовать во внешней среде: читать файлы, вызывать API, запускать скрипты, искать источники, обновлять таблицы, создавать отчеты. Интеллектуальность проявляется в способности планировать следующий шаг, учитывать результат предыдущего действия и при необходимости спрашивать человека.

## Слайд. Типичные архитектуры AI-агентов
Текст на слайде:
- ChatBot: диалоговая система, в основном отвечает текстом
- Copilot: ассистент внутри рабочей среды, помогает человеку выполнять действия
- ReAct: цикл “рассуждение -> действие -> наблюдение -> новое действие”
- MultiAgent: несколько агентов с разными ролями и зонами ответственности

Комментарии докладчика:
Эти архитектуры различаются степенью автономности. ChatBot подходит для объяснений и обсуждения. Copilot помогает внутри конкретной среды: кода, таблиц, документов. ReAct-агент сам выбирает инструменты и повторяет цикл до результата. MultiAgent-схема полезна, когда можно разделить роли: один агент ищет источники, второй проверяет лицензии, третий пишет код очистки, четвертый делает ревью.

## Слайд. ReAct как гибкая архитектура
Текст на слайде:
- ReAct: LLM принимает решение -> выполняет действие -> получает наблюдение -> повторяет цикл
- Может использовать произвольное количество инструментов
- Подходит для сложных workflows: поиск, очистка, запуск скриптов, отчеты
- Требует продвинутых моделей и строгого контроля
- Менее надежен, чем RAGBot или ChatBot, из-за вызова инструментов

Комментарии докладчика:
ReAct обычно наиболее гибкая архитектура, потому что агент не ограничен одним ответом. Он может решить: сначала прочитать README, затем посмотреть CSV, затем запустить проверку дублей, затем написать отчет. Но гибкость дает риск: инструмент может быть вызван не к месту, код может изменить файл, внешний API может вернуть шум. Поэтому ReAct-агентам нужны ограничения прав, логи действий, маленькие задачи и человеческое подтверждение для опасных операций.

## Слайд. Инструменты в агентских системах
Текст на слайде:
- Инструменты: функции или API, которые модель выбирает и вызывает через формальный контракт
- Тулза: функция с именем, описанием и JSON-схемой аргументов
- Позволяют агенту действовать во внешнем мире
- Бывают внутренними и внешними
- Расширяют возможности: файлы, браузер, OCR, ASR, таблицы, базы данных, Git
- Могут кэшировать информацию для оптимизации

Комментарии докладчика:
Инструмент - это не “любая возможность модели”, а описанный интерфейс: что можно вызвать, какие аргументы передать, какой результат получить. Например, агент может вызвать OCR для страницы, ASR для аудиофайла, поиск по корпусу, скрипт дедупликации или API таблицы. Формальный контракт важен: без него агент не действует надежно, а просто генерирует текст. Кэширование помогает не пересчитывать дорогие операции, например embeddings или результаты OCR для уже обработанных страниц.

В практическом смысле тулза - это функция с именем, описанием и JSON-схемой аргументов, доступная модели для выбора и вызова в ходе решения задачи. В экосистемах агентных фреймворков инструмент оборачивает произвольный код с явной схемой ввода-вывода, чтобы модель могла корректно сгенерировать параметры и получить машинно-обрабатываемый результат.
