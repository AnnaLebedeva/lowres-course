# Занятие 2. Веб-скрейпинг, сбор данных и правовая рамка

## Роль занятия в курсе
Занятие учит находить и собирать текстовые данные без разрушения качества и без нарушения прав. Главный результат - первый воспроизводимый пайплайн сбора корпуса и таблица источников.

## Лекция, 90 минут

### Слайд 1. Откуда берутся данные для малоресурсных языков
Текст на слайде:
- Сайты местных СМИ, администраций, школ, музеев
- PDF, учебники, словари, архивы
- Социальные сети и мессенджеры: только с явным согласием и осторожностью
- Полевые данные: речь, списки слов, тексты, переводы

Комментарии докладчика:
Для многих языков открытый веб-корпус мал или почти отсутствует. Поэтому сбор данных часто комбинирует веб, архивы, OCR и полевую работу. Нужно сразу отделять легальные открытые источники от материалов, которые нельзя публиковать.

### Слайд 2. Скрейпинг как исследовательский пайплайн
Текст на слайде:
1. Инвентаризация источников
2. Проверка правил доступа
3. Загрузка
4. Извлечение текста
5. Дедупликация
6. Языковая фильтрация
7. Документация

Комментарии докладчика:
Скрейпинг - не просто “скачать сайт”. Воспроизводимость важнее объема. Через месяц команда должна понимать, откуда взялась каждая строка и можно ли ее использовать.

### Слайд 3. Правила доступа и этика
Текст на слайде:
- Проверяем лицензии, Terms of Use, robots.txt
- Не собираем личные данные без необходимости
- Не публикуем чувствительные материалы
- Храним источник, дату, лицензию, ограничения

Комментарии докладчика:
Даже если технически можно скачать данные, это не значит, что их можно публиковать или использовать для обучения модели. Для летней школы нужно заранее подготовить шаблоны согласий и правила хранения.

### Слайд 4. Современные инструменты сбора
Текст на слайде:
- `trafilatura`, `newspaper`, `readability` для извлечения текста
- `BeautifulSoup`, `requests`, Playwright для сложных страниц
- Агент для обхода источников и составления отчета
- Таблица источников как контроль качества

Комментарии докладчика:
Студенты с базовым Python могут работать через готовые библиотеки и агента. Но они должны проверять результат: извлекся ли основной текст, не попали ли меню, реклама, комментарии, дубли.

### Слайд 5. Что сохранять вместе с текстом
Текст на слайде:
- URL
- Дата загрузки
- Заголовок
- Язык по источнику и язык по классификатору
- Лицензия или статус прав
- Хеш текста
- Версия пайплайна

Комментарии докладчика:
Метаданные позволяют потом чистить корпус, исключать спорные источники и воспроизводить датасет. Это особенно важно для малоресурсных языков, где каждый текст может сильно влиять на модель.

### Слайд 6. Риски веб-корпусов
Текст на слайде:
- Код-свитчинг
- Машинные переводы
- Повторяющиеся новости
- Тексты не на целевом языке
- Нестабильная орфография
- Непрозрачные права

Комментарии докладчика:
Большой корпус низкого качества может вредить больше, чем маленький корпус хорошего качества. Нужно учить студентов считать не только объем, но и долю шума.

### Слайд 7. Агентный сбор данных
Текст на слайде:
- Агент ищет источники
- Агент предлагает код загрузки
- Агент строит отчет о качестве
- Человек проверяет права, выборку и ошибки

Комментарии докладчика:
Агент полезен для рутинных шагов: составить список сайтов, написать скрипт, проверить формат. Но нельзя делегировать ему финальное решение о праве использования и качестве языкового материала.

### Слайд 8. Артефакт занятия
Текст на слайде:
- `sources.csv`
- `scrape_config.yaml`
- `raw_texts.jsonl`
- `scraping_report.md`

Комментарии докладчика:
Даже если команда собрала 20 текстов, это уже полезно, если они чисто описаны и воспроизводимы. Цель занятия - создать основу корпуса.

## Семинар, 90 минут

### Практика 1. Таблица источников, 20 минут
Каждая команда создает `sources.csv`:
- `source_id`
- `url_or_reference`
- `type`
- `language`
- `license`
- `access_notes`
- `risk_level`
- `owner`

### Практика 2. Сбор 5-10 документов, 30 минут
Команды используют готовый скрипт, агентный код или ручную загрузку. Минимальное требование - сохранить тексты в JSONL:
```
{"id": "...", "source": "...", "text": "...", "metadata": {...}}
```

### Практика 3. Проверка шума, 25 минут
Команды вручную размечают 20 фрагментов:
- целевой язык: да / нет / смешанный
- мусор HTML: да / нет
- дубликат: да / нет
- права понятны: да / нет
- годится для корпуса: да / нет

### Практика 4. Отчет агента, 15 минут
Промпт:
```
Проанализируй этот небольшой корпус для малоресурсного языка.
Найди признаки мусора, дублей, код-свитчинга и юридических рисков.
Сформируй отчет: что можно использовать сейчас, что требует проверки,
что нужно исключить. Не делай вид, что уверен в языке, если данных мало.
```

## Домашнее задание
1. Расширить список источников до 10-20.
2. Собрать минимум 30 документов или объяснить, почему это невозможно.
3. Подготовить `scraping_report.md` с рисками и планом очистки.
4. Выбрать один источник, который может стать основой для летней школы.

## Выход занятия
- `sources.csv`
- `raw_texts.jsonl`
- Первичная ручная оценка качества
- `scraping_report.md`

## Связь с летней школой
Занятие помогает понять, какие данные можно собрать до школы, а какие придется собирать на месте. Если веб-данных почти нет, летняя школа должна сильнее опираться на полевые записи, OCR архивов или работу с локальными экспертами.
